# Day1 프롬프트 — FDA GRAS 등록 심사 도메인용

교안 「Day1_교안.pdf」의 프롬프트 12개를 내 도메인·내 앱 함수에 맞춰 옮긴 것.
교안의 통신사 예시(모바일/데스크톱·요금제조회·절차 단축 실험·만족도 설문)는 이 도메인에 없다 →
GRN·체인·회사(Notifier) 그레인 / 제출→종결→결과_성공 단계 / bio·country 축으로 바꿨다.

## 이 도메인에서 계속 걸리는 것 — 실측 vs 합성

| 무엇 | 어디서 | 결론 근거로 |
|---|---|---|
| `kpis()` · `monthly()` | 실측 `GRASNotices` (GRN·체인 그레인) | **쓴다** |
| `funnel_by_vintage()` · `vintage_verdict()` | 실측 `GRASNotices` (GRN, 제출순 묶음) | **쓴다** |
| `retention_funnel()` · `retention_order_check()` | 실측 `GRASNotices` (회사 그레인, ⚠ 코호트 필터 없음) | 편향 함께 적으면 |
| `funnel()` · `funnel_by()` · `funnel_by_verdict()` | **합성** `funnel_events_synthetic` + `cases_synthetic` | **못 쓴다** — "합성·결론 근거 아님" 꼬리표 필수 |

실제 `GRASNotices`(건당 1행 스냅샷)를 이벤트 로그로 바꾸는 어댑터가 아직 없다(미정) →
축 분해(bio·country)는 화면에서 **합성으로만** 돈다. 이 사실 자체가 오늘 「못 쓰는 숫자」의 절반.

# 실습 A — 앱에서 숫자를 꺼낸다

## 🔻 프롬프트 1 — 지표 전수 (작업형)

```
core/metrics.py 를 직접 호출해서 아래를 전부 조회하고 표로 보여줘.

- kpis(t) 가 돌려주는 지표 6개 전부 — 이름 · 값 · 단위 · 표본 n
- 각 지표의 분자와 분모가 정확히 무엇인지, 그레인이 GRN 1건인지 체인 1건인지도 함께
- status_of(이름, 값) 로 각 지표의 상태 색(ok/warn/block)도
- monthly(t) 로 추이 — 이 함수는 월이 아니라 "종결연도별" 이다.
  마지막 3개 연도는 따로 표시하고, 접수일이 없어 값이 NaN 인 열도 그대로 보여줘

★ 화면에 뜨는 반올림 값이 아니라 함수를 직접 호출해서, 소수 둘째 자리까지.
★ "최종 성공률"(체인 그레인, 분모=해소된 체인)과 "최종 승인율"(GRN 그레인,
   분모=전체 접수 1,336)은 다른 지표다. 분모를 명시하지 않은 지표는 근거로 못 쓴다.
★ "평균 처리 일수"의 n 이 접수 건수(1,336)와 다르면, 왜 다른지 한 줄로.
```

**무엇을 볼까**: `평균 처리 일수` n 이 1,336보다 훨씬 작다 → 접수일이 2017년부터 비공개라
계산 가능한 건이 절반뿐. 이 지표는 최근을 못 본다 → 실습 D·한계로 간다.

## 🔻 프롬프트 2 — 퍼널과 이탈 (작업형)

```
두 가지를 나란히 보여줘.

(1) 합성 퍼널 — funnel(t["funnel_events_synthetic"]) 를 돌려서
    단계 | 도달 | 단계 전환율 | 누적 전환율 | 이탈 인원
    - 단계 전환율이 가장 낮은 구간(병목)
    - 이탈 인원이 가장 많은 구간
    - 둘이 같은 구간인가 다른 구간인가 ★

(2) 실측 퍼널 — GRASNotices 에서 직접 세어줘 (이벤트 로그가 아니라 cat 컬럼으로)
    제출 = 전체 GRN / 종결 = cat != "Pending" / 결과_성공 = cat == "no_questions"
    같은 표로: 단계 | 도달 | 단계 전환율 | 누적 전환율

그리고 회사 유지도 — retention_funnel(t) 와 retention_order_check(t) 결과도.

★ (1)은 합성 데이터다. 화면 병목 수치는 발견 근거로 못 쓴다.
   결론에 쓰는 병목은 (2)의 종결→결과_성공 이다.
★ (1)과 (2)의 병목 전환율 차이를 %p 로 적어줘.
★ 병목과 이탈 최다가 다른 구간이면, 구멍이 두 개다. 그 이유도 한 줄로.
```

**무엇을 볼까**: 실측 종결→결과_성공 ≈ 81% 가 이 퍼널의 병목. 제출→종결에서 빠지는 건은
탈락이 아니라 아직 심사 중(Pending). `retention_order_check` 가 "부분집합 성립"이면
단계 정의가 서로 포개져 있다는 뜻 — 순서 위반 0은 구조적이라 약한 근거다.

# 실습 B — 근거의 넷을 채운다 ★ 오늘의 장면

값 하나(전환율)를 **분자·분모 · 비교 대상 · 비중 · 표본** 넷이 붙은 문장으로 바꾼다.

## 🔻 프롬프트 3 — 분모 · 비교 · 비중 (작업형)

```
funnel_by() 로 병목 구간을 축별로 쪼개줘.

  fe = t["funnel_events_synthetic"], se = t["cases_synthetic"]
  구간: step_from="종결", step_to="결과_성공", missing_is_pending=False
  축(dim): "host_identified"(숙주식별/미분류), "country"(미국/해외)  — 한 번에 하나씩

각 축마다 이 형태로:
  칸 이름 | 도달 | 전환 | 전환율 | 비중 | 최고-최저 격차
그리고 funnel_by_verdict() 판정 배지(주목할 만함 / 차이 없음 / 감춘 칸)도.

★ "비중"이 무엇에 대한 비중인지 명시 — 전체 트래픽인가, 그 구간(종결) 도달자 중인가.
★ 격차가 가장 큰 축과 가장 작은 축을 둘 다 알려줘.
   격차가 작은 축("이 축으로는 안 갈린다")도 적어 둬라 — 그것도 결과다.
★ 이건 전부 합성 데이터다. GRASNotices 에도 bio·country 컬럼이 있지만
   스냅샷→이벤트 로그 어댑터가 없어 실측으로는 이 분해를 못 돌린다. 그 사실을 적어줘.
```

**무엇을 볼까**: `host_identified` 격차는 크게(주목), `country` 격차는 작게(안 갈린다) 나올
가능성이 높다. `country` 의 결측(nan)은 `(미매칭)` 한 칸으로 모이고, `미상`·`(미매칭)` 은
잔여 범주라 `trust_check` 가 감춘다 → 전환율·비중이 NaN.

## 🔻 프롬프트 4 — 표본을 흔들어 본다 (작업형)

```
프롬프트 3에서 나온 각 칸(사유 없이 값이 계산된 칸만)에 대해,
한 건이 바뀌면 전환율이 얼마나 흔들리는지 계산해줘.

  칸 | 도달(분모) | 한 건 흔들림 폭(%p) = 1/도달 × 100 | 칸 사이 격차(%p)

그리고 흔들림 폭이 칸 사이 격차보다 큰 축이 있으면 크게 표시해줘.

★ 그 축은 결론을 낼 수 없는 축이다.
★ 도달이 100 미만인 칸이 있으면, 비율로 쓰지 말고 "N건 중 M건"으로.
★ trust_check 가 이미 MIN_CELL(150) 미만·잔여 범주로 감춘 칸은 여기 넣지 마 —
   그건 프롬프트 7에서 따로 다룬다.
```

| 결과 | 무엇을 뜻하나 |
|---|---|
| 흔들림 < 격차 | 격차가 진짜다. 근거로 쓸 수 있다 (단, 합성이라는 꼬리표는 유지) |
| 흔들림 > 격차 | 못 쓴다. 표본이 더 필요하다 |
| 도달 100 미만 | 비율 대신 건수로 |

## 🔻 프롬프트 6 — 유효 구간 (작업형)

```
funnel_by_vintage(t) 와 vintage_verdict() 를 돌려서,

★ 안 찬 묶음(GRN 1287+)을 포함한 값과 제외한 값을 나란히 보여줘. 어느 쪽을 쓸지는 내가 정한다.
★ 8주차에 정한 유효 구간(GRN 1~1286, 판단기준.md 2026-09-03)을 적용한 값도 함께.
```

**무엇을 볼까**: 마지막 묶음(GRN 1287~1336)은 미종결 34/50 → `vintage_verdict` 가
"관측 중단". 반면 GRN 1137~1186 은 성숙했는데 종결→성공이 낮다 → "성과 확인 필요"
(절단이 아니라 진짜 저조). 이 둘을 구분 못 하고 "최근 성과가 나빠졌다"를 발견으로
적으면 틀린 제안이 나온다.

## 🔻 프롬프트 10 — 크기를 매긴다 (작업형)

```
발견마다 크기를 계산해줘.

  발견 | 격차 | 비중 | 격차 × 비중 | 절대 건수로 환산하면

절대 건수 환산 = 격차 × 그 구간 도달 건수 (예: 종결 도달 1,301건, 또는 전체 접수 1,336건 —
어느 쪽을 분모로 썼는지 명시).

★ 순서는 매기지 마. 표만 보여줘.
★ 격차가 큰데 비중이 작은 것, 비중이 큰데 격차가 작은 것을 각각 따로 표시해줘.
```

| 표가 이러면 | 다음 |
|---|---|
| 격차 × 비중이 뚜렷하게 큰 것이 하나 | 내일 그것부터 판다 |
| 다 비슷하다 | 축을 잘못 골랐을 수 있다 → 실습 B로 |
