# 내 도메인 프롬프트

교안의 프롬프트를 **이 도메인이 실제로 답할 수 있는 형태로** 고쳐 적는다.

- 회차마다 **덧붙인다.** 위를 고치지 않는다 — 사정이 바뀌면 새 날짜로 적고 무엇이 바뀌었는지 남긴다.
- 고칠 때는 **먼저 조회해서 확인한다.** 교안이 가정한 것과 내 데이터가 다른 지점을 숫자로 짚고,
  그 숫자를 프롬프트 안에 넣는다. 추측으로 고치면 프롬프트가 또 틀린 가정을 나른다.
- 회차 순서대로 아래에 쌓는다. Day1 은 따로 있던 파일을 2026-09-10 에 여기로 합쳤다.

---

## 이 도메인의 고정 사실 — 프롬프트를 고칠 때마다 걸리는 것

프롬프트를 새로 고칠 때 **매번 다시 확인하지 않아도 되는** 것들. 데이터가 바뀌면 여기부터 다시 잰다.

| 무엇 | 값 | 교안이 가정하는 것과 어떻게 다른가 |
|---|---|---|
| 퍼널 단계 | **3개** (제출 · 종결 · 결과_성공) | 교안 예시는 8단계. **구간이 2개뿐**이라 "구간 간 비교"가 한 쌍만 나온다 |
| 구간 전환율 | 제출→종결 **97.38%** · 종결→결과 **81.17%** | 병목은 종결→결과 하나 |
| 분해 축 | **`bio` · `country` 둘뿐** | `config.FUNNEL_DIMS` 에 있다 (2026-09-10 에 화면 두 곳에서 올림). ⚠ **합성/실측 컬럼 이름이 다르다** — `host_identified` ↔ `bio` |
| 축 격차 | `bio` **13.69%p** (통과) · `country` **1.50%p** (MIN_GAP 미달) | 쓸 수 있는 축이 사실상 하나 |
| `funnel()`·`funnel_by()` | **실측을 못 먹인다** (스냅샷→이벤트 로그 어댑터 미정) | 값 자체는 스냅샷에서 직접 세어진다 → CLAUDE.md 2026-09-08 |
| `monthly()` | 이름과 달리 **종결연도별** | 교안의 "최근 12개월"이 성립하지 않는다. 월평균 4건 |
| 마지막 해 | **2026은 반쪽** (종결일 최댓값 2026-07-06) | 증감 비교에서 뺀다 (판단기준 2026-09-03) |
| 평균 처리 일수 | **2019년부터 NaN** | 추세를 낼 수 없다 |
| 임계값 상태 | 셋 다 `ok` (79.04 / 18.26 / 176) | "임계값을 벗어난 지표" 갈래가 **0개**로 나온다 |
| 금액 | **컬럼 자체가 없다** | 규모를 금액으로 못 낸다. 건수로만 (Day3 부록 B) |
| 실험 | **없다** (무작위 배정 없음) | 실험 절을 만들지 않는다 |
| `PERIOD` | 1998-05-27 ~ 2026-07-06 = **28.1년** | 연간 환산 분모는 **최근 10 완결연도(2016~2025) 평균 연 67.2건** 을 쓴다. 전체 평균은 연 47.5건 |
| 표본 | 전체 **1,336건** · 종결 도달 **1,301건** | |

### 축이 될 만한 다른 컬럼을 찾아봤다 — 없다

전 컬럼을 훑어 "값이 2~12개이고 하한(`MIN_CELL` 150)을 넘는 칸이 둘 이상"인 것을 찾았다.

| 컬럼 | 왜 못 쓰나 |
|---|---|
| `Basis` | 값 5개지만 표기 흔들림 (`Scientific procedures` / `Procedures` / `procedurews`). 정규화하면 사실상 1칸 |
| `GRN Part 5~7` · `Additional correspondence 2` · `Related submission` | **결측 99%** |
| `cat` | 결과 그 자체다. 축으로 쓰면 순환이다 |

→ **축이 둘뿐인 것이 이 도메인의 실제 상태다.** 억지로 늘리지 않는다.

## 2026-09-08 (Day1) — 프롬프트 12개

교안의 통신사 예시(모바일/데스크톱 · 요금제조회 · 절차 단축 실험 · 만족도 설문)를
이 도메인으로 옮긴 것. 아래 네 가지가 교안과 달라 프롬프트를 고쳤다 —
그레인(GRN · 체인 · 회사) · 단계 3개 · 실험 없음 · 설문 없음.

#### 이 도메인에서 계속 걸리는 것 — 실측 vs 합성

| 무엇 | 어디서 | 결론 근거로 |
|---|---|---|
| `kpis()` · `monthly()` | 실측 `GRASNotices` (GRN·체인 그레인) | **쓴다** |
| `funnel_by_vintage()` · `vintage_verdict()` | 실측 `GRASNotices` (GRN, 제출순 묶음) | **쓴다** |
| `retention_funnel()` · `retention_order_check()` | 실측 `GRASNotices` (회사 그레인, ⚠ 코호트 필터 없음) | 편향 함께 적으면 |
| `funnel()` · `funnel_by()` · `funnel_by_verdict()` | **합성** `funnel_events_synthetic` + `cases_synthetic` | **못 쓴다** — "합성·결론 근거 아님" 꼬리표 필수 |

실제 `GRASNotices`(건당 1행 스냅샷)를 이벤트 로그로 바꾸는 어댑터가 아직 없다(미정) →
축 분해(bio·country)는 화면에서 **합성으로만** 돈다. 이 사실 자체가 오늘 「못 쓰는 숫자」의 절반.

### 실습 A — 앱에서 숫자를 꺼낸다

#### 🔻 프롬프트 1 — 지표 전수 (작업형)

```
core/metrics.py 를 직접 호출해서 아래를 전부 조회하고 표로 보여줘.

- kpis(t) 가 돌려주는 지표 6개 전부 — 이름 · 값 · 단위 · 표본 n
- 각 지표의 분자와 분모가 정확히 무엇인지, 그레인이 GRN 1건인지 체인 1건인지도 함께
- status_of(이름, 값) 로 각 지표의 상태 색(ok/warn/block)도
- monthly(t) 로 추이 — 이 함수는 월이 아니라 "종결연도별" 이다.
  마지막 3개 연도는 따로 표시하고, 접수일이 없어 값이 NaN 인 열도 그대로 보여줘

★ 화면에 뜨는 반올림 값이 아니라 함수를 직접 호출해서, 소수 둘째 자리까지.
★ "최종 성공률"(체인 그레인, 분모=해소된 체인)과 "최종 승인율"(GRN 그레인,
   분모=전체 접수 1,336)은 다른 지표다. 분모를 명시하지 않은 지표는 근거로 못 쓴다.
★ "평균 처리 일수"의 n 이 접수 건수(1,336)와 다르면, 왜 다른지 한 줄로.
```

**무엇을 볼까**: `평균 처리 일수` n 이 1,336보다 훨씬 작다 → 접수일이 2017년부터 비공개라
계산 가능한 건이 절반뿐. 이 지표는 최근을 못 본다 → 실습 D·한계로 간다.

#### 🔻 프롬프트 2 — 퍼널과 이탈 (작업형)

```
두 가지를 나란히 보여줘.

(1) 합성 퍼널 — funnel(t["funnel_events_synthetic"]) 를 돌려서
    단계 | 도달 | 단계 전환율 | 누적 전환율 | 이탈 인원
    - 단계 전환율이 가장 낮은 구간(병목)
    - 이탈 인원이 가장 많은 구간
    - 둘이 같은 구간인가 다른 구간인가 ★

(2) 실측 퍼널 — GRASNotices 에서 직접 세어줘 (이벤트 로그가 아니라 cat 컬럼으로)
    제출 = 전체 GRN / 종결 = cat != "Pending" / 결과_성공 = cat == "no_questions"
    같은 표로: 단계 | 도달 | 단계 전환율 | 누적 전환율

그리고 회사 유지도 — retention_funnel(t) 와 retention_order_check(t) 결과도.

★ (1)은 합성 데이터다. 화면 병목 수치는 발견 근거로 못 쓴다.
   결론에 쓰는 병목은 (2)의 종결→결과_성공 이다.
★ (1)과 (2)의 병목 전환율 차이를 %p 로 적어줘.
★ 병목과 이탈 최다가 다른 구간이면, 구멍이 두 개다. 그 이유도 한 줄로.
```

**무엇을 볼까**: 실측 종결→결과_성공 ≈ 81% 가 이 퍼널의 병목. 제출→종결에서 빠지는 건은
탈락이 아니라 아직 심사 중(Pending). `retention_order_check` 가 "부분집합 성립"이면
단계 정의가 서로 포개져 있다는 뜻 — 순서 위반 0은 구조적이라 약한 근거다.

### 실습 B — 근거의 넷을 채운다 ★ 오늘의 장면

값 하나(전환율)를 **분자·분모 · 비교 대상 · 비중 · 표본** 넷이 붙은 문장으로 바꾼다.

#### 🔻 프롬프트 3 — 분모 · 비교 · 비중 (작업형)

```
funnel_by() 로 병목 구간을 축별로 쪼개줘.

  fe = t["funnel_events_synthetic"], se = t["cases_synthetic"]
  구간: step_from="종결", step_to="결과_성공", missing_is_pending=False
  축(dim): "host_identified"(숙주식별/미분류), "country"(미국/해외)  — 한 번에 하나씩

각 축마다 이 형태로:
  칸 이름 | 도달 | 전환 | 전환율 | 비중 | 최고-최저 격차
그리고 funnel_by_verdict() 판정 배지(주목할 만함 / 차이 없음 / 감춘 칸)도.

★ "비중"이 무엇에 대한 비중인지 명시 — 전체 트래픽인가, 그 구간(종결) 도달자 중인가.
★ 격차가 가장 큰 축과 가장 작은 축을 둘 다 알려줘.
   격차가 작은 축("이 축으로는 안 갈린다")도 적어 둬라 — 그것도 결과다.
★ 이건 전부 합성 데이터다. GRASNotices 에도 bio·country 컬럼이 있지만
   스냅샷→이벤트 로그 어댑터가 없어 실측으로는 이 분해를 못 돌린다. 그 사실을 적어줘.
```

**무엇을 볼까**: `host_identified` 격차는 크게(주목), `country` 격차는 작게(안 갈린다) 나올
가능성이 높다. `country` 의 결측(nan)은 `(미매칭)` 한 칸으로 모이고, `미상`·`(미매칭)` 은
잔여 범주라 `trust_check` 가 감춘다 → 전환율·비중이 NaN.

#### 🔻 프롬프트 4 — 표본을 흔들어 본다 (작업형)

```
프롬프트 3에서 나온 각 칸(사유 없이 값이 계산된 칸만)에 대해,
한 건이 바뀌면 전환율이 얼마나 흔들리는지 계산해줘.

  칸 | 도달(분모) | 한 건 흔들림 폭(%p) = 1/도달 × 100 | 칸 사이 격차(%p)

그리고 흔들림 폭이 칸 사이 격차보다 큰 축이 있으면 크게 표시해줘.

★ 그 축은 결론을 낼 수 없는 축이다.
★ 도달이 100 미만인 칸이 있으면, 비율로 쓰지 말고 "N건 중 M건"으로.
★ trust_check 가 이미 MIN_CELL(150) 미만·잔여 범주로 감춘 칸은 여기 넣지 마 —
   그건 프롬프트 7에서 따로 다룬다.
```

| 결과 | 무엇을 뜻하나 |
|---|---|
| 흔들림 < 격차 | 격차가 진짜다. 근거로 쓸 수 있다 (단, 합성이라는 꼬리표는 유지) |
| 흔들림 > 격차 | 못 쓴다. 표본이 더 필요하다 |
| 도달 100 미만 | 비율 대신 건수로 |

#### 🔻 프롬프트 6 — 유효 구간 (작업형)

```
funnel_by_vintage(t) 와 vintage_verdict() 를 돌려서,
가장 최근 묶음의 값이 앞 묶음보다 낮게 나오는 지표가 있는지 봐줘.

있으면 각 묶음마다:
- 그 묶음이 아직 안 찬 것인가 (제출→종결 < 90% = 관측 중단) —
  낮은 누적 성공은 실패가 아니라 Pending 때문이다
- 성숙했는데(제출→종결 ≈ 100%) 종결→성공이 성숙 묶음 중앙값보다 5%p 넘게 낮은가
  (= 시간 문제가 아니라 실제 저조)

★ 안 찬 묶음(GRN 1287+)을 포함한 값과 제외한 값을 나란히 보여줘. 어느 쪽을 쓸지는 내가 정한다.
★ 8주차에 정한 유효 구간(GRN 1~1286, 판단기준.md 2026-09-03)을 적용한 값도 함께.
```

**무엇을 볼까**: 마지막 묶음(GRN 1287~1336)은 미종결 34/50 → `vintage_verdict` 가
"관측 중단". 반면 GRN 1137~1186 은 성숙했는데 종결→성공이 낮다 → "성과 확인 필요"
(절단이 아니라 진짜 저조). 이 둘을 구분 못 하고 "최근 성과가 나빠졌다"를 발견으로
적으면 틀린 제안이 나온다.

### 실습 D — 못 쓰는 숫자를 가린다

#### 🔻 프롬프트 7 — 감춘 항목 (작업형)

```
프롬프트 3~4에서 trust_check() 가 못 믿을 조건으로 감춘 칸을 전부 보여줘.

  무엇이(어느 축·어느 칸) | 어느 조건에 걸려서 | 지금 몇 건인가 | 무엇이 채워지면 판정 가능한가

조건 값: MIN_CELL=150 (칸 도달 하한) · MAX_PENDING_RATIO=0.05 (미결 비율 상한) ·
잔여 범주("(미매칭)" · "미상")

★ 감춰진 전환율·비중 값 자체는 적지 마. 조건 값과 건수만.
★ 지금 내가 근거 후보로 들고 있는 숫자 중에, 감춘 칸에서 나온 것이 있으면 표시해줘.
★ vintage 의 "관측 중단" 묶음(GRN 1287+)도 사실상 감춘 항목이다 — 함께 적어줘.
```

파라미터(`?axis=`)가 그 값을 쓰고 있어 키를 바꾸면 공유된 링크가 깨진다.

### 교안 확인란이 이 도메인에서 어떻게 되나

| 교안 확인란 | 이 도메인에서 |
|---|---|
| 후보가 5개 미만이면 축이나 구간을 덜 본 것 | **적게 나오는 것이 정상이다.** 축 2 · 구간 2 · 임계값 0 |
| 기각된 후보가 목록에 남아 있는가 | `country` (격차 1.50%p, MIN_GAP 미달)가 반드시 남아야 한다 |
| 규모가 연간 건수로 나왔는가 | 누적(1,336)이 아니라 연간으로. 분모는 위 표에서 정한 것 |

### 프롬프트

```
core/metrics.py 에 topic_evidence(t, topic) 를 추가해줘.
proposal_topics() 가 돌려준 후보 하나(topic)를 받아, 제안서가 쓸 근거를 한 번에 모은다.

 현황  그 주제가 속한 퍼널 전체 — 단계 · 도달 · 전환율 · 병목 표시
    ⚠ 실측은 GRASNotices 스냅샷에서 직접 센다 (_real_funnel 재사용).
      단계가 셋(제출·종결·결과_성공)이라 구간이 둘이고 병목은 하나다.

 원인  분해 축 표 — 칸 · 도달 · 전환 · 전환율 · 비중 · 최고/최저 표시
    ⚠ **주제 갈래마다 다르다:**
        ② 분해 축 주제   -> topic["근거축"] 그 축 하나
        ① 퍼널 구간 주제 -> 근거축이 없다. 그 구간을 config.FUNNEL_DIMS 의
                           축 전부로 쪼갠 표를 준다 (축이 둘뿐이다)
        ③ 임계값 · ④ 추세 주제 -> 분해 축이 없다. None 으로 두고 사유를 적어라
    ⚠ 실측 컬럼은 FUNNEL_DIMS 의 "real" 값이다. 키(합성 컬럼 이름)를 그대로 쓰면
      KeyError 가 나거나 엉뚱한 컬럼을 센다.
    ⚠ trust_check 를 그대로 적용해라. 못 믿을 칸은 전환율·비중을 만들지 말고 사유만.
      (계산해 놓고 숨기는 것이 아니라 꺼낼 값을 안 만든다)

 규모  연간 건수 + 환산에 쓴 가정 목록
    ⚠ topic 이 이미 갖고 있다(규모_연간건수 · 가정). **다시 계산하지 마라** —
      두 곳에서 계산하면 언젠가 갈라진다. 그대로 실어라.
    ⚠ 규모가 None 인 주제(나빠지지 않아 재지 않은 것)는 None 을 그대로 두고 사유를 적어라.
      0 으로 바꾸지 마 — 0 은 "작다"고 읽히는데 실제로는 "질문이 성립 안 한다"다.

 추세  관련 지표의 **연도별** 값
    ⚠ monthly() 는 이름과 달리 종결연도별이다. "최근 12개월"은 이 도메인에 없다.
    ⚠ 마지막 해는 반쪽이다(종결일 최댓값 2026-07-06). 빼지 말고 싣되
      **반쪽이라는 표시를 함께** 달아라. 비교에는 쓰지 않는다.
    ⚠ 평균 처리 일수 열은 2019년부터 NaN 이다. 그 지표가 대상이면 None + 사유.
    어느 지표를 보나:
        ③ 임계값 · ④ 추세 주제 -> 그 지표 자체
        ① 구간 · ② 축 주제     -> 그 구간의 결과에 해당하는 지표(최종 승인율)

★ 없는 것은 지어내지 말고 None 으로 두되, **왜 없는지 사유를 같이 넣어라.**
   None 만 있고 사유가 없으면 다음 사람이 버그인 줄 안다.
★ 실측과 환산값을 같은 항목에 섞지 마. 키를 나눠라 —
   현황 · 원인 · 추세는 **실측**, 규모는 **환산**이다.
★ 이 함수는 **조회만 한다. 문장을 만들지 않는다.** 문장은 report/proposal.py 가 만든다.
★ 같은 표를 두 모양으로 돌려주지 마라. 화면과 문서가 같은 것을 본다.
```

### 이 도메인에서 None 이 실제로 나오는 자리

교안 확인란이 "네 항목이 다 나왔는가 / 없으면 사유가 붙어 있어야 한다"인데,
이 도메인은 **None 이 반드시 나온다.** 사유가 붙는지가 확인 지점이다.

| 항목 | 언제 None 인가 |
|---|---|
| 원인 | 주제가 ③ 임계값 · ④ 추세 갈래일 때 (분해 축이 없다) |
| 규모 | 주제가 기각된 추세일 때 (나빠지지 않아 재지 않았다) |
| 추세 | 대상 지표가 평균 처리 일수일 때 (2019년부터 NaN) |
| 현황 | **없다** — 실측 퍼널은 항상 셀 수 있다 |
